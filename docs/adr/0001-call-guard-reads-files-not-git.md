# Сторож читает файлы репозитория, а не запускает `git`

Status: accepted

Отказ на вызов, состоящий из одного `cd`, отдаёт ветку, наличие `.git` и готовую строку
`git -C <каталог> status --short --branch` (#87 п.1). Факты берутся из файлов: ветку даёт `.git/HEAD`,
воркдерево — указатель `gitdir:` в файле `.git`, отсутствие каталога — `existsSync`. Процессов сторож
не запускает: в `extensions/call-guard-core.mjs` нет ни `child_process`, ни `exec`.

Альтернатива — вызвать `git status --short --branch` внутри сторожа — точнее: она отдала бы и «грязно
или чисто». От неё отказались по цене: сторож срабатывает на каждом вызове bash, а `git status` стоит
секунды в большом репозитории (в msb-lk — самый частый вызов после `read`) и умеет висеть на битом
индексе, сетевом каталоге или чужом lock-файле. Отказ сторожа, который сам может зависнуть, дороже
потерянного хода, ради которого правило и написано. Состояние правок агент получает копированием
строки из отказа — ровно тем вызовом, который он и собирался сделать.

Побочно: чтение файлов не зависит от `PATH`, версии git и настроек машины, поэтому правило одинаково
себя ведёт в CI и на хосте, и тест на него не требует живого репозитория (в `tests/call-guard.test.mjs`
каталог с `.git/HEAD` создаётся во временном каталоге).
